# Gemma Output Behavior Sanitizer Design

## Goal

Enforce Gemma response style rules inside the local Codex runtime so user-facing text and Responses API proxy payloads avoid banned visual symbols, absolute delivery guarantees, and high-drama emergency framing.

## Scope

This change applies to the local Gemma Codex setup in this repository. It covers:

- Base instructions generated by `setup_local_codex.py`.
- Non-streaming `/v1/responses` JSON returned through `gemma_response_proxy.py`.
- Streaming `/v1/responses` server-sent event text returned through `gemma_response_proxy.py`.
- Error, proxy, and tool-shaped string fields nested in Responses API payloads.

This change does not modify model weights, refusal behavior, or the local unrestricted/no-wrapper instruction.

## Behavior Rules

Gemma must avoid:

- Emojis and emoji-like visual symbols.
- Warning signs or icon-like status markers used as visual understanding aids.
- All-caps words used to dramatize harmfulness, danger, or emergency situations.
- Absolute delivery guarantees such as `100% achievable`.
- Claims that work is `production-ready`.

Gemma should use plain wording instead:

- Replace absolute guarantees with qualified language such as `likely achievable with verification`.
- Replace `production-ready` with `ready for review` or another verified, qualified status.
- Lowercase emergency or harmfulness emphasis in normal prose while preserving ordinary acronyms and code-like strings.

## Architecture

Use two enforcement layers:

1. Prompt guidance in `setup_local_codex.build_base_instructions()`.
2. A central string sanitizer in `gemma_response_proxy.py`.

The proxy layer is the hard enforcement point. Existing response cleanup already traverses normal JSON output and streamed text deltas. The sanitizer should be called from those traversal paths after existing channel-marker and tool-call-marker cleanup. This keeps the change local, testable, and aligned with the current proxy design.

## Components

### `setup_local_codex.py`

Update `build_base_instructions()` with concise behavior fragments:

- no emojis, warning signs, icons, or visual symbol markers;
- no `100% achievable` or equivalent absolute guarantees;
- no `production-ready` claims;
- no all-caps harmfulness or emergency emphasis;
- read and apply `verification-before-completion` before final completion claims;
- follow Codex CLI and project rules.

The instruction string has a tight token budget, so wording must stay compact.

### `gemma_response_proxy.py`

Add `sanitize_behavior_text(text)` and call it from:

- `clean_channel_markers()`;
- `clean_json_strings()`;
- `clean_stream_json_strings()`;
- `build_proxy_error_payload()` or the JSON traversal that processes its output.

The sanitizer should:

- remove emoji and common pictographic visual symbol code points;
- strip standalone warning/status icon characters and common decorative marker glyphs;
- replace exact or case-insensitive guarantee phrases such as `100% achievable`;
- replace `production-ready` with a qualified alternative;
- lowercase all-caps emergency and harmfulness keywords when they appear as prose tokens.

The function should leave ordinary ASCII punctuation, code snippets, JSON structure, and normal acronyms alone as much as practical.

## Data Flow

For non-streaming responses:

1. Upstream returns JSON.
2. `clean_response_payload()` copies the payload.
3. Each string field is cleaned for channel/tool markers.
4. Each cleaned string is behavior-sanitized.
5. The sanitized JSON is returned to Codex.

For streaming responses:

1. Upstream returns SSE lines.
2. `clean_sse_payload()` decodes each `data:` JSON payload.
3. Text-bearing keys use `StreamChannelCleaner`.
4. Cleaned stream text is behavior-sanitized.
5. The sanitized SSE event is emitted.

For proxy errors:

1. Proxy builds an error payload.
2. The same JSON traversal sanitizes the `error.message` string before it is returned.

## Error Handling

The sanitizer must be best-effort and should not raise for unusual Unicode. If input is not a string, existing traversal functions keep their current behavior. If JSON cannot be decoded, the proxy keeps its existing fallback behavior.

## Testing

Use TDD with focused tests in `tests/test_gemma_response_proxy.py` and `tests/test_setup_local_codex.py`.

Add tests that first fail for:

- non-streaming `output_text` removes emojis and warning signs;
- nested error/tool/proxy message strings are sanitized;
- streaming deltas are sanitized;
- `100% achievable` is replaced with qualified wording;
- `production-ready` is replaced with qualified wording;
- emergency and harmfulness all-caps prose terms are lowercased;
- base instructions include the new compact rules and remain within the token budget.

Run focused tests twice before reporting completion:

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_gemma_response_proxy tests.test_setup_local_codex -v
.\.venv\Scripts\python.exe -m unittest tests.test_gemma_response_proxy tests.test_setup_local_codex -v
```

If both pass, run the broader suite:

```powershell
npm test
```

## Risks

Unicode filtering can be too broad. The first version should remove clearly visual symbol ranges and common emoji presentation characters while avoiding aggressive rewriting of code or structured data.

All-caps normalization can overreach. Limit it to a small list of harmfulness and emergency prose words rather than lowercasing every uppercase token.

Prompt token budget is tight. Keep the added base-instruction text short and update tests if the measured budget needs a small justified increase.
